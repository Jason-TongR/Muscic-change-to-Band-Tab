# 旧网页版与命令行使用说明

[返回项目首页](../README.md)

本页仅说明保留的浏览器和命令行入口。桌面版的启动、分享项目和用户数据位置请看[项目首页](../README.md)或[桌面版说明](DESKTOP.md)。下列命令均在项目根目录执行。

给乐队排练用的音频转谱工具。导入音乐，在浏览器里跟随原曲看吉他六线谱、贝斯谱、键盘/人声音高与鼓点；逐音修改后导出。中文界面，音频在本机处理，不需要 API key 或付费服务。

**定位：可校正的转写草稿与排练工作台，不是保证准确的官方总谱。** 特别是失真吉他、多把吉他叠录、鼓组、推弦和滑音，仍需听辨复核。

## 启动

在本项目目录运行：

```bash
bash scripts/start.sh
```

打开 <http://127.0.0.1:8765>。点击「体验一段原创 Riff」即可体验；这段音频和谱子是程序预先合成/编写的，**不作为自动转写的准确率证明**。

首次在其他电脑使用，先安装基础依赖（Python 3.10+）：

```bash
bash scripts/install.sh
bash scripts/start.sh
```

整首乐队录音建议安装 AI 模式（Linux/macOS 脚本）：

```bash
bash scripts/install_ai.sh
bash scripts/start.sh
```

安装脚本在项目内创建 Python 3.11 与 `.venv-ai`，安装 CPU 版 PyTorch、Demucs、Basic Pitch、ONNX Runtime 等，不修改系统 Python。依赖和模型需要数 GB 磁盘，首次联网下载较慢。已有服务需先 Ctrl+C 停止，再启动以切换引擎。

- 浏览器左下显示引擎状态。没有完整依赖时，AI 模式不能提交，不会偷偷用基础算法代替。
- 默认 CPU。CUDA 需要自行安装与本机显卡驱动相配的 PyTorch/torchaudio，再选择 NVIDIA CUDA。安装脚本提供的是 CPU 版。
- 支持 WAV / MP3 / FLAC / M4A / AAC / OGG / OPUS / AIFF。解码器优先使用系统 FFmpeg，否则使用 `imageio-ffmpeg` 随包的版本；缺少解码器时仅支持可读的 WAV。
- 每段最多 200 MB、15 分钟。长曲建议先截取 30–60 秒验证效果；超长音频会报错，不会默默截断。
- 仅绑定 `127.0.0.1`，不是公网托管应用。

## 三种模式

| 模式 | 适用输入 | 实际处理 | 局限 |
| --- | --- | --- | --- |
| 基础旋律 | 单音吉他、贝斯或人声录音 | YIN 周期估计、音量门限、稳定音符分段 | 不分轨、不识别和弦里的多个音，混音只供参考；全部音符标待复核 |
| 单乐器多音 | 已经分离的吉他/键盘等音轨 | Basic Pitch 多音符转写 | 不分轨；不适用于直接区分混音里的各乐器 |
| 完整乐队 | 完整歌曲混音 | Demucs `htdemucs_6s` 六轨分离；吉他/贝斯/键盘/人声接 Basic Pitch；鼓轨频段起音估计 | 六轨不等于六份准确谱，鼓只有三条参考通道，其他伴奏只供试听 |

完整模式使用 librosa 的逐拍时间估计，支持把变速拍点用于可视化和量化；节拍估计可能倍速/半速，拍号和重拍需确认。基础模式估计恒定 BPM。和弦只匹配大三/小三和弦模板，不推断完整和声。

## 推荐排练流程

1. 尽量用无损录音；若已有独立吉他或贝斯轨，优先使用它，避免分离误差。
2. 设置实际调弦（标准 / Drop D / 降半音）、变调夹和拍号。有可靠 BPM 可手动填写。
3. 先听首小节，在「节拍校正」中核对 BPM、第一小节重拍时间和拍号。修改 BPM 或首拍会改用恒定网格，音符真实时刻不变。当前拍号单位固定为四分音符：6/4 不是 6/8。
4. 打开「分轨」，用 **M** 静音、**S** 独奏。分轨模式下原曲不会再叠加发声。0.5×–1.25× 慢放使用浏览器保调速率播放。
5. 点击波形或谱面跳转；设置 A、B，然后开启循环。谱面可缩放、选择单个声部或展示总谱。
6. 点击音符编辑实际音高（MIDI）、时间、力度、弦/品；支持添加、删除、撤销。橙色表示待复核；`?` 表示无可用指法。
7. 点击保存；切换曲目与导出前也会自动保存。关页前有未保存修改会提示。编辑是改谱，不会重新合成或改变原始录音的声音。

**快捷键：** 空格播放/暂停；左右方向键前后跳 3 秒。输入框、按钮焦点或弹窗内不抢占快捷键。

六线谱上方是 1 弦。变调夹的品数与图上品位相加才是相对原琴枕的实际品数；音高始终为实际发声音高。指法通过束搜索优先保留可弹音符，兼顾和弦弦号冲突、持续占弦、手型跨度和把位移动。不随意改八度来塞进指板；无法分配时保留原音并标记待复核。这个算法估计可行指法，不能还原录音者实际用的指法。

## 导出与存储

- **MIDI**：保留实际音符开始/结束时间与力度，多声部独立轨，鼓使用第 10 通道。使用固定 120 BPM 时间编码保证秒级时值，**不导出原曲的变速 tempo map**。DAW 导入后显示的 BPM 不代表原曲 BPM。
- **MusicXML 4.0**：十六分音符网格，独立声部/复音 voice，跨小节连音，吉他/贝斯弦号品位。音频首拍前的弱起目前归入第一小节；不会完整还原连音、三连音、装饰音或特殊奏法。鼓为底鼓/军鼓/踩镲。可在支持 MusicXML 的制谱软件中继续整理；尚不保证所有软件的排版一致。
- **文本 TAB**：按小节的十六分网格，`?` 提示复核，末尾保留无法分配指法的音符。
- **项目 JSON**：机器可读备份，保留原始秒数、网格坐标与音轨路径，不内嵌音频。网页版没有 JSON 导入界面；在网页版间迁移需复制完整项目目录。迁移到桌面版时可打开原目录中的 `project.json`，前提是音频仍在原位置；之后可导出包含音频的 `.bandtab` 项目包。

项目存储在 `data/<项目编号>/`：`project.json`、原始上传、解码后的音频和分离轨。`data/models/` 缓存 Demucs 模型；`data/cache/` 是计算缓存。服务重启后可从曲库打开完成的项目；进行中的任务不会自动续算。失败详情在项目目录 `error.log` 和 `separation.log`。取消分轨会终止子进程，取消神经网络推理会等待当前 30 秒片段完成。

删除某个 `data/<项目编号>/` 文件夹即可删除本地项目；这些数据、模型、依赖和缓存均被 Git 忽略。

## 命令行批处理

```bash
# 基础单音吉他
bash scripts/start.sh "你的录音.wav" --mode preview --instrument guitar --bpm 120

# 完整混音（需已安装 AI 引擎）
bash scripts/start.sh "你的歌曲.mp3" --mode band --tuning drop_d --device cpu

# 单独的贝斯轨
bash scripts/start.sh "bass.wav" --mode instrument --instrument bass

# 使用其他端口
bash scripts/start.sh --port 8766
```

命令行输出项目目录和 MIDI、MusicXML、文本谱；启动界面后也能从曲库打开这些项目。

## 开发与验证

无前端构建依赖，界面只使用本地 HTML/CSS/JavaScript；后端 Python 标准库 HTTP 服务，按队列串行运行识别以限制内存峰值。

```bash
python3 -m unittest discover -s tests -v
node --check web/app.js
```

测试包含：已知音高合成音的真实转写、静音、调弦与变调夹、同时发声/持续占弦、不可弹音保留、时间映射、编辑数据校验、MIDI 结构、MusicXML 小节平衡/连音、本地 HTTP 上传转写与分段播放、保存导出、跨站限制。测试可在 `.venv-ai/bin/python` 下运行。HTTP 测试需要允许本机端口。

**测试音频的结果不能外推为真实歌曲的准确率。** 对真实乐队录音还需要基于人工标注曲目的评测。

## 依赖与技术依据

- [Demucs 官方仓库](https://github.com/facebookresearch/demucs)：`htdemucs_6s` 增加吉他和钢琴。官方明确这是实验性六声部模型，钢琴分离可能有明显串音与伪影。
- [Spotify Basic Pitch 官方仓库](https://github.com/spotify/basic-pitch)：轻量多音高转写，最适合单个乐器音轨；本项目在分轨后转写，并显式使用随包 ONNX 模型。
- [librosa 官方文档](https://librosa.org/doc/0.10.2/generated/librosa.beat.beat_track.html)：节拍检测。

不调用第三方音乐服务，不抓取歌曲；首次安装/模型下载需要联网，已下载后推理在本地执行。
